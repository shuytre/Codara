# 立项：PTC 预设（程序化工具调用，run_code）

> 对应规格：3.1 预设表「PTC：对外仅暴露 run_code，模型写 TypeScript 程序一次编排多步工具，v2 评估」。

## 范围

- 新预设 `ptc`：模型可见工具**仅 `run_code`**。
- `run_code`（主进程执行）：模型提交 TypeScript 子集程序 → 受控运行时执行 → 程序内可调用的内置 API 即现有工具（read/write/search/terminal/git/index.*）→ 返回执行结果（console 输出 + 工具调用流水 + 统一信封）。
- 执行环境：
  - 独立 Node 子进程（隔离崩溃与资源），单次执行超时默认 120s 上限 300s。
  - 可用 API 白名单：`codara.*`（工具桥接，逐次走完整工具管道——schema/角色/网关/审计/预算不减配）、基础库（无网络模块、无 fs 直连、无 child_process）。
  - 循环内单任务工具轮次计入任务预算（防一次性海量调用绕过熔断）。
- 提示词：PTC 系统提示词（程序结构规范：先探查后批量、失败早停、输出结论+证据）。

## 非目标

- 不做通用沙箱安全边界（禁止网络/fs 直连靠运行时白名单 + 真实安全边界仍由 sidecar 工具管道承担）。
- 不做并行编排原语（串行 await 为主，v2 观察需求）。

## WBS

1. 子进程执行器：ts-transpile（esbuild 已有）→ vm/worker 隔离运行 + 超时强杀 + 资源上限。
2. `codara.*` 桥接 API（与 ToolRuntime.execute 对齐，流水回传）。
3. `run_code` RPC + 预设/角色接线 + 审计（程序源码全量入审计）。
4. 提示词与示例库（3–5 个典型编排样例内置）。
5. 测试：执行器单测（超时/非法 API/预算扣减）+ 集成（mock 工具编排 round-trip）。

## 验收标准

- 程序内 10 次工具调用一次往返完成，总轮次计 1（模型视角）但预算按 10 次工具扣。
- 调用未授权 API（fs/network）运行时报错且不入审计外的任何副作用。
- 工具网关审批在程序执行中照常生效（弹卡即暂停，拒绝即程序收到错误）。
- 超时强杀后主进程不受影响。

## 风险与体积成本

- 风险：模型生成的程序质量（提示词+样例库兜底；失败退回标准预设）；vm 隔离非硬安全边界（口径明确：安全由工具管道与 sidecar 承担）。
- 体积：主进程增量 <200KB（esbuild 已在依赖内）。
- 工期：1.5 周。
- 立项节奏：**v2 评估项**——建议先在内部以实验开关（`developer.ptcPreview`）灰度，收集成功率后转正。
